# The Kanban Guide (May 2025)

Source: https://kanbanguides.org/english/

---

## Definition of Kanban

Kanban is a strategy for optimizing the flow of value through a process. It comprises three practices working in tandem:

1. Defining and visualizing a workflow
2. Actively managing items in a workflow
3. Improving a workflow

Those who participate in the value delivery of a Kanban system are called **Kanban system members**.

---

## Why Use Kanban?

**Flow** is the movement of potential value through a system. Kanban optimizes value by optimizing flow across three dimensions:

- **Effectiveness** — delivers what stakeholders want when they want it
- **Efficiency** — allocates available economic resources as optimally as possible
- **Predictability** — accurately forecast value delivery within an acceptable degree of uncertainty

---

## Kanban Practices

### 1. Defining and Visualizing the Workflow

The explicit shared understanding of flow among Kanban system members is called a **Definition of Workflow (DoW)**. At minimum, a DoW must include:

- A definition of the individual units of value moving through the workflow (**work items**)
- A definition of when work items are **started** and **finished**
- One or more defined **states** that work items flow through (any item between started and finished is **work in progress / WIP**)
- A definition of how **WIP will be controlled**
- **Explicit policies** about how work items can flow through each state
- A **Service Level Expectation (SLE)** — a forecast of how long it should take a work item to flow from started to finished (e.g., "85% of work items finished in 8 days or less"), based on historical cycle time

The visualization of a DoW is a **Kanban board**.

### 2. Actively Managing Items in a Workflow

- Control WIP — start work only when there is capacity (pull system)
- Ensure work items do not age unnecessarily (use SLE as reference)
- Unblock blocked work
- Review active items regularly

### 3. Improving the Workflow

Continuously improve the DoW to achieve a better balance of effectiveness, efficiency, and predictability. Changes can be made just-in-time — no need to wait for a formal cadence.

---

## Flow Metrics

Four mandatory metrics:

| Metric | Definition |
|---|---|
| **WIP** | Number of work items started but not finished |
| **Throughput** | Number of work items finished per unit of time |
| **Work Item Age** | Elapsed time between when a work item started and the current date |
| **Cycle Time** | Elapsed time between when a work item started and when it finished |

---

## Key Terms

- **Work item** — the individual unit of value flowing through the workflow
- **WIP (Work in Progress)** — any item between a started and finished point
- **DoW (Definition of Workflow)** — the explicit shared understanding of flow
- **SLE (Service Level Expectation)** — a probabilistic forecast of cycle time
- **Pull system** — new work is started only when capacity exists, not pushed in
